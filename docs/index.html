02 / Ultra HDR JPEG

The HDR information now survives thumbnailing

Gain map verified

An SDR screenshot can look similar before and after. The measurable change is that the new JPEG retains a usable gain map, allowing an HDR-capable viewer to reconstruct highlights.

Actual gain map from the new thumbnail

The 180 × 101 gain map carries extra HDR information alongside the 720 × 405 SDR image. The old thumbnail has no usable gain map.

Reconstruction succeeded with a peak scRGB channel value of 14.58; SDR white is 1.0. This is decoded image data, not a measurement of display brightness.

The new thumbnail is 26,825 bytes versus 25,050 bytes before: +1,775 bytes (+7.1%) for this sample. Both fit the app’s 100 KB thumbnail target. Full-image conversion also preserves the gain map with the new binary.

The embedded new JPEG is the original HDR-preserving output. Its appearance depends on browser, OS and display support. No synthetic brightness enhancement is applied. The change does not itself enable HDR display throughout Photos.

Method, binaries and sample provenance

Downloaded the old files from the published release and the new files directly from the tag build. Each executable ran on a matching OS and architecture. All images use identical input bytes, verified by SHA-256.

vips copy input.raw output.jpeg
vips thumbnail input.raw 'output.jpeg[Q=70]' 720 --size down

For Ultra HDR, the new decoder inspected outputs from BOTH versions:
vips uhdr2scRGB output.jpeg reconstructed.v
vips max reconstructed.v

RAW filenames retain their real extensions, such as .nef or .cr2. The old HDR output fails reconstruction with “gainmap-max-content-boost not found”. The original HDR sample and new outputs reconstruct successfully. A gain map was also extracted from the new output. Visual inspection checks the SDR rendering; HDR display has not been tested on a physical screen.
